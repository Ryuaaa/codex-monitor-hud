# Windows 原生版：Codex 只读数据接入里程碑

当前 Windows 版使用 **Win32 + C++17** 构建常驻悬浮窗，已经具备主页、Codex、电脑性能三页、十六个可配置模块、真实性能采样，以及通过本机官方 `codex app-server` 读取 Codex 额度、订阅、官方 Token 日汇总和最近任务历史的第一版能力。

它不会提取、保存或显示提示词、回复、工具内容、账号邮箱、任务标识、工作目录、会话路径或原始接口行。额度趋势只在本机保存采样时间、剩余百分比和恢复时间，不保存账号或任务内容。

## 已实现

### 窗口与模块

- 默认置顶，可随时切换置顶；支持标准标题栏拖动、任意边角连续等比缩放、主窗口位置/大小锁定、真正最小化到任务栏、单实例和应用图标。缩放最小为 75%，最大值按当前显示器工作区动态计算，窗口、字号和卡片一起缩放。
- 支持 `Home`、`Codex`、`Computer` 三页，重启后恢复当前页、窗口位置/大小和置顶状态。
- 十六个模块包括“电脑压力、主要瓶颈与 Codex/ChatGPT 影响”诊断卡、CPU/内存、10 分钟 CPU 趋势、网络与磁盘实时速度、CPU/内存进程排行等六个性能明细卡，以及 Codex 五小时额度、每周额度、额度趋势预测、订阅类型、账号 Token 用量、Token 用量与费用（Beta）、当前任务活动（本机推测）、最近任务历史和 OpenAI 官方服务状态九个模块。
- 每个模块分别提供“显示在主页”和“显示在所属页面”两个开关；五小时额度与每周额度互不绑定。
- 原有电脑性能模块和“10 分钟 CPU 趋势”默认在新安装的主页和电脑页显示；“网络与磁盘实时速度”默认显示在电脑页，主页默认关闭但可自行加入。新安装时，主页同时显示五小时额度、每周额度和当前任务活动；Codex 页默认显示五小时额度、每周额度、额度趋势、订阅、Token 用量与费用（Beta）、当前任务活动、最近任务历史和 OpenAI 官方服务状态。账号 Token 用量默认关闭，费用模块默认不加入主页。已有或损坏的设置不会自动开启新增趋势卡。
- 设置使用版本化白名单格式保存到 `%LOCALAPPDATA%\CodexMonitorHUD\settings.ini`；当前格式为版本 11。旧版设置迁移时保留用户已有模块选择、五小时/每周额度独立状态、版本 9 外观设置和窗口位置，并把版本 8 及更早的独立宽高安全重建为 100% 等比窗口。版本 10 中已经完整启用的周额度提醒会原样迁移；版本 8、版本 9 及损坏或不完整的提醒设置仍保持默认关闭。
- 卡片按换行后的真实文字动态增高；长费用、任务和错误说明使用像素级滚动条与鼠标滚轮，不截断也不按整行跳动。布局和设置字号同时跟随窗口等比缩放与每台显示器的 DPI。
- 设置提供四角位置预设、70% / 82% / 90% / 100% 整体透明度，以及低饱和蓝、绿、紫、橙四种主题；主窗口也可直接切换位置/大小锁定。
- 自动检查发现新版时，主窗口显示醒目的可点击横条；只有用户点击横条或设置按钮才打开设置。后台自动检查、重复启动和更新结果不会强制抢到前台。
- 启动、显示器布局改变和 DPI 改变时，窗口会约束到可见工作区；损坏或越界的保存值会安全回退。

### 电脑性能

- 单一串行后台线程采样，窗口消息线程不执行系统指标读取。
- 每 5 秒读取整机 CPU、物理内存、进程列表、Codex/ChatGPT 进程树与进程 I/O，以及整机下载/上传和物理磁盘读/写累计计数；每 20 秒读取系统提交量、页面文件和全部进程的 CPU/工作集排行。进程 I/O 复用已经打开的只读进程句柄，只增加一次轻量原生计数读取，不等同于物理磁盘吞吐。
- “10 分钟 CPU 趋势”直接复用上述 5 秒整机 CPU 样本，只在内存中保留最近 600 秒并压成最多 18 桶；显示实际连续采样时长、有效样本均值和峰值，不写文件、不增加线程或计时器。时间使用排除睡眠的单调系统计时；采样倒退、间隔超过 30 秒、页面停采或最小化都会开始新段，缺失值不会被画成 0%。
- “网络与磁盘实时速度”直接复用上述 5 秒串行采样显示下载、上传、磁盘读和磁盘写，不增加线程或联网请求。首次采样、性能采样恢复、网卡切换、计数器重置或异常时间间隔会先显示“正在建立基线”；接口全部不可用时明确显示不可用，不伪装成 `0 B/s`。
- 汇总 Codex/ChatGPT 进程树的整机 CPU 份额、工作集内存、内存最大的子进程及读写 I/O 速度；另显示整机 CPU 前三和工作集前五进程，帮助判断瓶颈来自 Codex 还是其他程序。CPU 排行复用 20 秒慢采，不新增线程。
- 使用同一批现有数据给出当前压力、CPU/内存瓶颈、Codex/ChatGPT 合计影响和置信度；它不增加采样或网络请求。数据不足时明确显示未知，不把单帧趋势写成持续故障。
- 两次慢采之间或慢采失败时保留上次有效的提交量、页面文件和内存排行，不闪成不可用。
- 后台采样不重入；工作线程忙时只合并必要请求，完整慢采优先。
- 窗口最小化、当前页不需要性能数据，或主页没有性能模块时，停止定时器、取消未执行请求并使在途旧结果失效；恢复需求后立即重建 CPU 基线并进行完整首采。
- 受保护进程、权限不足或采样间进程退出只让对应指标降级，不让整帧失败。
- Windows 没有适用于所有硬件的统一热压力接口，因此明确显示 `system not provided`，不伪造温度或热压力等级。

### Codex 官方只读数据

- 直接启动本机绝对路径的 `codex.exe app-server --stdio`，完成官方 `initialize` / `initialized` 握手后读取：
  - `account/rateLimits/read`：五小时与每周额度剩余比例、恢复时间；
  - `account/read`：订阅类型；
  - `account/usage/read`：官方每日 Token 汇总；
  - `thread/list`：最近任务历史。
- 五小时与每周额度独立显示；接口未返回某个窗口时明确显示“当前未返回”，不会用另一个窗口或 `0` 代替。
- 额度趋势复用现有 5 分钟额度刷新，不增加网络请求。每个恢复周期至少积累 3 个点且跨度达到 15 分钟后，分别显示“近期平稳”“可撑到恢复”或“可能提前用完”，并标出低、中、高置信度；恢复时间变化后自动进入新周期。
- 周额度消耗提醒默认关闭，用户可设置 5–100% 阈值（默认 15%），并选择“滚动 24 小时”或“自然日”。它复用现有 5 分钟额度刷新，不增加额外轮询；数据不足、额度恢复或读数不单调时不提醒，同一自然日或滚动 24 小时周期只提醒一次，周额度重置后进入新周期。
- 额度历史位于 `%LOCALAPPDATA%\CodexMonitorHUD\quota-usage-history.txt`，只保留最近 30 天、最多 10,000 个白名单样本，并以临时文件原子替换。趋势模块不可见且提醒关闭时停止采样和写入；提醒开启后即使悬浮窗隐藏或最小化，也只按原有 5 分钟节奏维持额度与历史采集。
- 防重复状态位于 `%LOCALAPPDATA%\CodexMonitorHUD\weekly-quota-alert-state.txt`，只保存恢复时间、模式和提醒时间，不复制额度、Token、账号或任务数据。只有 Windows 通知设施已注册时才评估；达到阈值后先原子保存下一状态，再发不抢前台且尊重系统安静时段的通知。原子保存失败不通知，通知提交失败会尝试恢复旧状态；通知设施不可用时不弹出、也不记为已提醒。
- Token 卡显示今日数据；若今日尚未结算，则显示官方最近一次有数据的日期，并同时显示近 7 日、近 30 日、本月累计和按当前月内日均线性外推的“月末约”趋势，不把缺失数据写成今日 `0`，数据不足时也不生成预测。
- “Token 用量与费用（Beta）”优先使用官方每日汇总作为各周期 Token 总量，再用本机会话中的模型和输入/输出结构估算 API 等价费用；费用不是 Pro 订阅账单。未知模型不会硬套价格，而会降低计价覆盖率。
- 本机会话扫描只查看 `codexHome` 下近 30 天的 `sessions/YYYY/MM/DD/rollout-*.jsonl` 和近期 `archived_sessions/*.jsonl`。每轮最多读取 64 MiB、单行最多保留 512 KiB；增量游标和已经冻结的费用样本以版本化白名单缓存保存到 `%LOCALAPPDATA%\CodexMonitorHUD\codex-cost-history-cache.txt`，上限 8 MiB，并以临时文件原子替换。缓存不存在或损坏时安全回退到一次有界扫描，未知版本不会被覆盖。`.jsonl.zst` 暂不解压，并明确标记覆盖不完整。
- `thread/list` 每次最多请求五条；界面最多显示三条经过清理和截断的名称及最近时间。任务状态只可能反映本次短生命周期 `app-server` 进程的范围，界面明确提示它不代表 Codex 桌面版的全局实时任务状态。
- “当前任务活动（本机推测）”与上述五分钟账户接口解耦：只在该卡片当前可见且窗口未隐藏、未最小化时，由独立串行线程检查 `%USERPROFILE%\.codex\sessions` 当天和前一天目录。它先按文件修改时间筛选相对当前时间前后 120 秒内的候选，再最多读取 64 个普通 `.jsonl` 文件的末尾 1 MiB；只解析 `timestamp`、记录类型、角色和阶段，不提取或保存提示词、回复、工具内容、路径或原始行。
- 最近会话存在未解压的 `.jsonl.zst`、无法安全打开的文件或超过候选上限时，卡片显示“部分可确认”或“当前无法可靠判断”，不会把缺失记录报告成可靠的 `0`。存在可确认活动时每 5 秒检查，空闲或无法判断时每 20 秒检查；隐藏卡片会取消在途结果并停止后续扫描。
- 单个方法失败不会清空其他方法；已有成功值时继续显示上次数据并标明本次更新失败。
- 成功后每 5 分钟刷新；连续失败按 1、2、5、10、15 分钟退避并封顶，下一次成功后恢复 5 分钟正常刷新，避免故障期间持续创建进程。
- Codex 数据与性能数据分别按需运行。提醒关闭时，窗口最小化、当前页不需要 Codex 数据或相关模块全部隐藏会取消在途读取并停止后续刷新；周额度提醒开启时仅保留原有 5 分钟额度刷新，关闭提醒后恢复普通显隐停采规则。

### OpenAI 官方服务状态

- 只请求 `https://status.openai.com/api/v2/summary.json`，优先显示 `Codex in ChatGPT Desktop` 组件状态，同时保留 OpenAI 整体状态，帮助区分官方服务异常与本机问题。
- 请求不携带账号、令牌或 Cookie，关闭自动认证与重定向，响应上限为 1 MiB；解析失败或出现未来未知状态时不会显示为“正常”。
- 成功后 15 分钟再检查；连续失败按 1、2、5、10、15 分钟退避并封顶。失败时保留上次成功状态和时间，同时明确标注“更新失败”。
- 该模块默认显示在 Codex 页、主页默认关闭；只有它在当前页面实际可见且窗口没有隐藏或最小化时才启动请求。隐藏后不再安排新请求，在途同步请求会在约 8 秒的有界超时内结束且结果丢弃；15 分钟内切回会复用新鲜状态，不会因反复切页重复联网。

### `codex.exe` 查找与进程安全

- 优先接受绝对路径的 `CODEX_CLI_PATH`，其次检查绝对 `PATH` 目录，再检查已知的官方桌面版、打包应用、本机 standalone release 和 npm 用户级安装布局。
- 自动发现最多检查 64 个候选，只查看固定目录或一层版本目录；不递归扫描磁盘、不执行 `where`、脚本或命令行外壳，也不尝试受保护的 `WindowsApps` 目录。
- 候选必须是绝对路径、普通文件，且路径不经过重解析点；版本目录中选择最新的安全候选。
- 子进程通过 `CreateProcessW` 直接启动，只继承明确列出的管道句柄，并在恢复执行前加入“关闭即清理”的 Windows Job，暂停、超时或退出时不会遗留 `app-server` 子进程。
- 单行接口数据限制为 1 MiB、输出队列和总输出有固定上限、保留的标准错误最多 16 KiB、单次读取总时限 15 秒；原始接口内容不会传到界面或落盘。

## 数据口径

| 指标 | Windows 接口或来源 | 口径 |
| --- | --- | --- |
| 整机 CPU | `GetSystemTimes` | 对相邻累计时间做差，扣除空闲时间并限制为整机 0–100%；第一帧没有差值，明确不可用。 |
| 10 分钟 CPU 趋势 | 上述整机 CPU + `QueryUnbiasedInterruptTime` | 复用 5 秒样本并仅保存在内存；最多 600 秒、18 个平均桶，睡眠时间不计入覆盖时长，无偏间隔超过 30 秒时开始新段。 |
| Codex/ChatGPT CPU | `GetProcessTimes` | 对进程编号和创建时间一致的相邻累计值做差，再除以同一帧整机 CPU 总时间差；100% 表示整台机器的逻辑处理能力接近占满。 |
| Codex/ChatGPT 进程 I/O | `GetProcessIoCounters` | 对同一进程编号和创建时间的累计传输字节做 5 秒差值；进程新增、退出或计数重置时标记为部分值或重新建立基线。它包含进程层 I/O，不冒充物理磁盘吞吐。 |
| 整机 CPU 进程排行 | `GetProcessTimes` | 每 20 秒对全部可读进程建立独立基线，显示整机 CPU 份额前三；新进程和身份不连续的进程不参与当次差值。 |
| 物理内存 | `GlobalMemoryStatusEx` | 已用量为总物理内存减去当前可用物理内存。 |
| 系统提交量 | `GetPerformanceInfo` | 显示当前提交量、提交上限和开机后峰值，不等于页面文件大小。 |
| 页面文件 | `EnumPageFilesW` | 汇总所有页面文件的总量、当前使用量和峰值。 |
| 整机下载/上传 | `GetIfTable2` | 汇总当前可用且非回环、非过滤接口的累计字节，再按相邻 5 秒样本计算速度；网卡集合变化后重新建立基线。 |
| 物理磁盘读/写 | PDH 英文 `PhysicalDisk(_Total)` 原始累计计数 | 使用持久查询读取累计字节，再按相邻 5 秒样本计算速度；计数器重置或性能采样恢复后重新建立基线。 |
| 进程列表 | `CreateToolhelp32Snapshot` | 只读取进程编号、父进程编号和可执行文件名，不读取命令行。 |
| 进程内存 | `GetProcessMemoryInfo` | 使用工作集做趋势和排名；共享页可能重复计入，不等于独占内存。 |
| 一眼诊断 | 上述 CPU、物理内存、提交量与 Codex/ChatGPT 进程树指标 | 保守的当前快照启发式判断；工作集归因置信度最高为中，不等于证明某一个应用是长期瓶颈。 |
| Codex 额度/订阅/Token/任务历史 | 本机官方 `codex app-server --stdio` | 只保留界面需要的最小字段；接口缺失与数值 `0` 严格区分。 |
| Codex 当前任务活动 | `%USERPROFILE%\.codex\sessions` 的近期普通 JSONL | 本机趋势推测；120 秒活动窗、最多 64 个候选、每文件尾部最多 1 MiB，压缩或不可读记录使结果降级而不是误报为 0。 |
| Token 模型样本与费用 | `codexHome` 内白名单会话 JSONL | 只提取时间、模型和 Token 计数；不保留路径、任务正文、账号或原始 JSON。 |
| Codex 额度趋势 | 上述额度的本机白名单历史 | 只判断当前恢复周期近 24 小时的变化趋势；至少 15 分钟历史，不等于官方承诺或精确耗尽时间。 |
| Codex 周额度消耗提醒 | 当前周额度与上述本机白名单历史 | 用户选择滚动 24 小时或本地自然日；基线必须接近周期起点，数据不足或非单调时宁可漏报，不会把估算当成账单。 |
| OpenAI 服务状态 | `status.openai.com/api/v2/summary.json` | 公共只读状态；Codex 组件优先，组件缺失时明确回退到 OpenAI 整体状态。 |

在超过 64 个逻辑处理器且划分为多个处理器组的机器上，`GetSystemTimes` 只覆盖调用线程所属的主要处理器组；当前桌面版尚未做跨处理器组校准，不能把这类工作站的读数当作整机精确值。

## 为什么继续使用 Win32

- 不嵌入网页引擎，不要求 Electron、WebView2、.NET 或 Windows App SDK；
- 性能指标、窗口和用户设置均使用 Windows 文档化接口；
- 高频工作保持在单一可停止的后台线程中，只有界面实际需要时才运行；
- 官方 Codex 读取也在独立串行线程中短时执行，不阻塞窗口消息。
- 当前任务活动使用另一个按显隐启停的轻量串行线程；目录元数据先筛掉旧文件，常态不会读取 64 × 1 MiB。

## 在 Windows x64 上构建

需要 Windows 10/11、Visual Studio 2022 Community 或 Build Tools、`Desktop development with C++`、Windows 10/11 SDK 和 CMake。

在仓库根目录运行：

```powershell
cmake -S windows -B windows/out/build -A x64
cmake --build windows/out/build --config Release
ctest --test-dir windows/out/build -C Release --output-on-failure
./windows/out/build/Release/CodexMonitorHUD.exe
```

正式发布构建还必须在 CMake 配置时传入发布证书的 64 位十六进制 SHA-256 指纹，例如 `-DCODEX_MONITOR_WINDOWS_PUBLISHER_SHA256=<指纹>`。没有该固定值时，内部更新助手按设计拒绝安装，不会退化成“信任任意有效签名”。

仓库的 Windows x64 CI 会执行源码契约检查、MSVC Release 编译、全部测试、EXE 存在性验证并上传临时构建产物。ARM64 尚未进入支持和发布范围。

CI 还会生成 `CodexMonitorHUD-windows-x64.zip`，其中包含EXE、许可证和本说明，并同时生成 `.zip.sha256` 校验文件。正式发布中的便携包包含已签名EXE；便携版可以检查新版，但不会启用“安装更新”，一键安装只对从MSI安装目录启动的版本开放。

Windows 自动更新只读取 `windows-v版本号` 发布；普通 `v版本号` 保留给 macOS，避免两个平台相互误判版本。

每次准备新更新前会低成本清理旧临时目录：只识别 `update-` 加 32 位小写十六进制字符的普通目录，重解析点或异常内容一律跳过；七天内的目录不会删除，并始终保留最新两个。清理失败不影响悬浮窗或本次更新。

在 Windows 本机完成 Release 编译后，也可运行：

```powershell
./windows/package-release.ps1 `
  -BinaryPath "windows/out/build/Release/CodexMonitorHUD.exe" `
  -OutputDirectory "windows/out/release"
```

Windows CI 还会使用 WiX 生成当前用户范围的 MSI，静默安装到临时目录，核对已安装 EXE 与测试产物一致，再执行卸载并确认程序文件已移除。开发分支产物会明确标为 `unsigned`，签名前不作为正式公开安装包。

本机装有 WiX Toolset 3 时可运行：

```powershell
./windows/build-installer.ps1 `
  -BinaryPath "windows/out/build/Release/CodexMonitorHUD.exe" `
  -OutputDirectory "windows/out/installer"
```

仓库已经提供手动触发的 `Windows signed release` 工作流。它把GitHub托管运行器产生的EXE和MSI提交给SignPath.io，先取得真实发布者证书SHA-256，再把它固定进更新器并重新构建、重新签名。MSI由已经签名的EXE构建，SignPath项目必须使用仓库中的[`signpath-artifact-configuration.xml`](signpath-artifact-configuration.xml)，配置名称固定为`windows-release-v1`；它签署便携EXE和包含该EXE的MSI外壳。最后独立核验EXE与MSI的Authenticode签名、发布者指纹、真实旧版升级、安装后EXE签名、卸载和校验值后才创建GitHub Release。缺少SignPath凭据、审批或可信签名时会直接失败，不会发布未签名正式包。

## Windows 机器上的最小验收

1. 在真实 Windows x64 上启动 CI 产物，确认应用图标、单实例、任务栏最小化、置顶切换和退出正常。
2. 在不同窗口大小和 DPI 下切换 Home、Codex、Computer；确认窗口、字号和卡片保持等比，长文字完整且可以像素滚动，四边和四角拖动连续缩放。
3. 在设置中分别切换每个模块的主页和所属页开关、调整主页顺序、四角位置、透明度、主题与位置/大小锁定，重启后确认恢复；五小时与每周额度必须能独立选择。
4. 与任务管理器及资源监视器抽样对照整机 CPU、物理内存、提交量、页面文件、下载/上传、磁盘读/写、Codex/ChatGPT 进程树和内存前五名；切换网卡或让性能采样暂停后恢复时应先显示“正在建立基线”，并检查诊断卡没有在数据不足时误报“正常”或错误归因给某一个应用。
5. 在已登录 Codex 的机器上对照官方界面检查额度、订阅和 Token 日期/汇总；今日未返回时不得显示为 `0`。保持趋势卡可见至少 15 分钟，确认开始给出五小时和每周的独立趋势。
6. 检查最近任务只显示名称与最近时间，且不把 `app-server` 进程范围的状态写成桌面版全局实时状态；同时运行和结束一个 Codex 任务，确认“当前任务活动”在约 5 秒内变化，压缩或暂不可读记录不会显示成可靠的 0。
7. 对照 OpenAI 官方状态页检查 Codex 组件和整体状态；隐藏状态模块、隐藏窗口或最小化时确认不再发起状态请求，恢复后立即刷新。
8. 先关闭周额度提醒，再切换到不需要数据的页面、隐藏所有相关模块和最小化窗口，确认性能采样与 Codex 子进程停止；恢复后立即取得新数据。
9. 开启周额度提醒，分别检查 5–100% 滑块、滚动 24 小时和自然日设置能在重启后恢复；最小化后只应维持 5 分钟额度刷新。通知不得抢前台；数据不足、同一周期重复检查和系统通知设施不可用时不得误弹或误记。
10. 模拟接口失败，确认旧值保留、失败提示出现、没有残留 `codex.exe app-server`；恢复后能重新刷新。
11. 把窗口移到第二块显示器后退出，拔掉该显示器再启动，窗口应完整回到可见工作区。

## Code signing policy

Windows正式发行将使用SignPath.io提供的免费代码签名，证书由SignPath Foundation提供。签名文件必须来自本仓库公开标签和GitHub托管运行器；团队角色、人工批准、隐私和发布验证要求见[`../CODE_SIGNING_POLICY.md`](../CODE_SIGNING_POLICY.md)。
